## 📌 2026-06-26 · 记录同步机制 Hook 化（混合方案）

> 主题：把「每次改动 / 新任务都要同步记录」从纯靠 `CLAUDE.md`/skill 的**概率性指令**，升级为「**指令(怎么写) + Hook(何时逼写)**」混合——用确定性 hook 堵住"改了忘记录"的失败模式。延续上一条 06-26「评估 hook 化」的待拍板项。

- 🔷 **`[决策]` 记录同步采用「指令 + Hook」混合，非 hook 替代**（用户拍板）— 写记录是判断性工作（`[决策]` 要写谁拍板 / 为什么 / 否决了什么），shell hook 写不出，留在 `CLAUDE.md`/skill；但"何时该记录、改了没记就别收尾"是确定性触发，交给 hook。**否决了**：纯 hook 自动生成记录（写不出像样的决策条目）。
- 🔷 **`[决策]` 强制度 = 硬阻断 + `[skip-record]` 逃生口**（用户拍板）— commit 含实质改动却没动 `记录/` → 直接拦下（exit 2）；琐碎提交在 message 加 `[skip-record]` 放行。**否决了**：只提醒不阻断（退回概率性）、硬阻断不留逃生口（琐碎提交也被卡）。
- 🔷 **`[决策]` hooks 放项目共享 `settings.json`、入 git**（用户拍板）— 随仓库走、只对本项目生效、队友 clone 即得同款记录纪律。**否决了**：放全局（污染其它项目）/ 放 `settings.local.json`（不分享、不进版本库）。
- 🔷 **`[决策]` 先只上 A+B 两层，不加 Stop 提醒**（用户拍板）— 先观察 SessionStart 注入 + commit 守卫，避免一上来太多 hook；不够再加。
- 🟢 **`[活动]` 写 + 测 + 装记录同步 hook** — 新建 `.claude/settings.json`（SessionStart + PreToolUse 两 hook；已核实三层 hooks 合并执行，不破坏全局 hook）、`.claude/hooks/record-guard.js`（commit 守卫，Node 跨平台、fail-open、剥离引号防误报）、`.claude/hooks/session-record-ctx.js`（开局注入记录铁律 + git 漂移摘要）、`.claude/hooks/README.md`。先派 `claude-code-guide` agent 从官方文档核实 hook 能力，再实测 18 项断言全过；本会话即生效（守卫当场拦下自身测试命令）。

## 📌 2026-06-09 · 团队会议(三段录音)

> ⭐ **核心决策来源。** 完整记录见 `Atlas/神像供奉游戏 - 设计讨论记录 2026-06-09.md`。

- 🔷 **`[决策]` 世界观** — 诗人传授智慧后乘船离开(未死)、精神存于纪念雕像;玩家 = 神像(诗人化身);白天石像实体收贡(开门)/ 夜晚灵体加工(关门)。**为什么**:比 v2「知识被窃 + 空白容器」更顺、更利于「被供奉快感」的玩法。
- 🔷 **`[决策]` 岛屿 4+1 结构** — 五门类(视觉 / 表演 / 文学 / 设计应用 / 媒体与综合),前 4 个来供奉,「媒体与综合」作为较现代门类不来供奉、前来捣乱,引出科技 / AI 故事线。
- 🔷 **`[决策]` 上贡者四级稀有度**(团队认为基本决定项目成败)— 不稀有 / 稀有 / 很稀有(约 10)/ 极其稀有(按岛对称约 4-5)。**为什么**:让「开门看谁来上贡」具备抽卡 / 收集吸引力。**原则**:避免阶级感、隐晦呈现、稀有角色带艺术隐喻、可为动物 / 吉祥物。
- 🔷 **`[决策]` 材料与成品双线收集** — 材料外观统一、光效区分稀有度;材料不必转化(可收藏);初版只做小麦。成品也分稀有度;极稀有角色产出须独一无二而非仅加工更快。
- 🔷 **`[决策]` 加工玩法** — 宠物 = 可变形加工机(面包机 / 唱片机,至少 4 岛各一种),夜晚出现、村民不可见;内置「有缺陷的 AI」做艺术教育(讲解 + 对话提信仰)。
- 🔷 **`[决策]` 进度防封顶**(趋于共识)— 弃「按稀有度堆进度」(会封顶导致流失),改**解锁式进度**:达成阶段解锁新角色、名气招来更稀有的人、出新角色须配套新艺术品。对话必须手动人为;信仰等级 2 后村民才供材料;以学换币;限刷(每天至少工作 5 分钟,想一直刷要付钱)。
- 🔷 **`[决策]` 三阶段规划** — ① 单机养成(当前核心)→ ② 社区型(玩家互访空间、社交化)→ ③ 世界观 + 故事线;可能额外做深度绑定的社交软件。**A 认为**最终做成社交媒体 / 社区潜力大于单纯一个游戏。
- 🔷 **`[决策]` 技术路线** — 先用 **3D 模型**试做最小 demo(2D/live2D 费人手,模型可复用),场景固定视角,先把「开门 → 白天 → 一圈人走过来」骨架实现给大家看。
- 🔷 **`[决策]` 昼夜跳过**(未完全定论)— 初期不做跳过、改宠物自动化托管(做得越少回报越少);A 趋于共识、B 保留意见「先做出来再看」。
- 🔷 **`[决策]` 分工** — 王欣然—人物设计;李宇哲—符号设计;待招美术总监;用户—代码 / 最小 demo。
