# 初始版内容指导（最小可玩版 · MVP 规格）

> **这是什么**:第一个可玩版（最小 demo）到底做哪些内容的**范围说明书 + 实现指导**。
> 提炼自 Obsidian `Atlas/庙宇供奉游戏构想.md`（2026-06-09 约 10 分钟录音，A 口述 / B 确认）。
> 已**剔除法律 / 保密 / 股权**相关内容（那部分见 `法律文件/`，不在本指导范围）。
>
> **权威顺序**:`design/项目主旨.md`（最高）＞ 本指导（初版范围）。术语以主旨第十一节为准。
> 与 PLAN 的关系:本指导是 `PLAN.md` **Phase 2「最小 demo」**的细化规格。

## 一、一句话定位

> 你扮演庙宇中被供奉的**神像（诗人的化身）**:白天石像开门接受信众供奉,夜晚关门、化为灵体,指挥可变形宠物把供品加工成作品。

初版只求**把这条完整链路跑通**,数值与花活后置。

```
白天开门 → 信众成群到来、手持供品 → 点击信众 → 供品入绿色区域
        →（可选）对话 / AI 提问 → 提升信仰值 / 换更好供品 → 信众离开
夜晚关门 → 神像化灵体 + 宠物出现 → 拾取绿色区供品入物品栏
        → 点宠物 → 变面包机 → 投料 →（约50s）→ 产出成品
        → 拾取成品 → 再点 → 变唱片机 → 播放
（循环往复;信仰值持续积累,产出可升级）
```

---

## 二、场景与昼夜状态

场景本体是一个**长方体空间**（任意房间 / 庙宇模型即可），靠一面墙的「开 / 合」切换昼夜:

| 状态 | 庙门 | 光照 | 用途 |
|------|------|------|------|
| ☀️ **白天（开门）** | 长方体侧面打开（庙门敞开） | 外部光线进入 | 接待信众、收供奉 |
| 🌙 **夜晚（关门）** | 那一面合上（庙门关闭） | 室内自身灯光 | 回收、加工、产出 |

- 开口要**足够大**（不是一扇小门）,以便信众成群走进、停留、再走出。
- 初版不纠结模型精度,3D 占位素材即可,**固定视角**。

---

## 三、白天玩法:信众与供奉

**信众节奏**
- 信众**成群结队**到来（如 2–3 个一组），**错落站立**（非整齐排队 / 平行）走近。
- 每位信众**手持一件供品**走来。
- 视角始终**从神像（石像）出发**。

**供奉与对话（点击驱动）**
1. **点击信众** → 其把手中供品放入庙内一块**指定的绿色区域**。
2. 镜头拉近到信众面前,下方弹出对话框（如「你好」）。
3. 玩家获得一个**可打字的对话框**,回应后结束本轮。
4. 「到来—供奉—对话」流程**可重复多次**。

**AI 对话（关键设计点）**
- 信众的提问**不固定**,可由 **AI 动态生成**。
- 与信众的 AI 对话用于**提升神像「信仰值」**（可成长的核心数值）。
- 回应质量影响结果:**回答让信众满意,可能获得更好的供品**。

> [!note] 初版取舍
> AI 提问、信仰值是**明确方向但非第一版强制**。满意度 → 更优产出的「积攒式调养系统」**初版后置**。

---

## 四、夜晚玩法:回收与加工

关门后,神像**化为灵体形态**（诗人灵体），与身旁**宠物**一同产出:

1. **回收**:玩家 + 宠物从绿色区域**拾取**白天积累的供品 → 供品从绿色区消失,进入**物品栏 / 保管处**。
2. **加工**:点击**宠物（一条狗）** → 变形为**面包机**（加工装置）→ 投入材料。
3. **产出**:约 **50 秒**后,材料转化为**成品**（初版:唱片 / 面包）。
4. **播放**:拾取成品回物品栏 → **再点面包机** → 变形为**唱片机**播放。
5. *(v3 补充方向)* 宠物内置「有缺陷的 AI」**讲解作品**。

> [!tip] 初版最小链路
> **只做一种材料（小麦）+ 一种宠物形态 + 一台面包机 + 一种成品**,先把上面 5 步跑顺即可。

---

## 五、交互与视角原则（重要）

- **点击式交互**:玩家通过**点击**驱动一切,角色「办事」时自行行动。
- **不要自由操控移动**:明确**区别于《原神》**（可自由操控走位）——角色无需手动走位。
- 也**区别于《旅行青蛙》**的纯放置式——本作靠点击主动推进。

## 六、时间与数值参数（示例值,可调）

| 环节 | 示例时长 | 说明 |
|------|---------|------|
| 单个信众停留 | 约 10 秒 | 到位后原地停留 |
| 走入 / 走出 | 各约 5 秒 | 进场 / 离场移动 |
| 白天来访窗口 | 约 20 分钟 | 一段完整供奉时段 |
| 夜晚加工 | 约 50 秒 | 材料 → 成品 |

> 这些数值都是**示例**,最终取值待定（见进度「开放问题」）。

## 七、初版优先级

**第一要务 = 先把核心机制跑起来**:把上述庙宇供奉、回收加工的**完整链路**实现出来。

**初版后置（明确方向但非第一版强制）**:
- 信众的具体数量与到来频率
- 「满意度 / 信仰值」如何量化、如何驱动产出升级（积攒式调养系统）
- 各时间参数的最终取值
- AI 对话的接入方式与内容边界
- 供品 / 成品升级带来的更优 outcome

## 八、与 v3 主旨的对齐与待澄清

> 本指导忠于 06-09 录音原意,但部分点与后续 v3 决策需对齐——**不擅自定,标出来**:

1. **跳过键 vs 初期不做跳过** ⚠️
   构想里有**跳过键**:玩家不互动时,信众仍自行到来、按「相应程度」留下供品后离开（互动是加成项,非必需）。
   但 v3 倾向**初期不做跳过、改宠物自动化托管**（开放问题 #2,未定案）。
   → **初版到底做不做跳过键,需团队拍板**。

2. **神像昼夜形态**
   构想只说「石像 / 神」和「夜晚这个人 + 宠物」。v3 已细化为:**白天石像、夜晚化诗人灵体**。本指导已按 v3 表述对齐。

3. **「面包机产出唱片」的载体逻辑**
   构想中面包机加工出的是**唱片**。v3 多媒介载体体系下,面包纹路对应音乐、成品可为面包 / 唱片。初版沿用录音原案即可,载体归类留待 `系统机制.md` 统一。
