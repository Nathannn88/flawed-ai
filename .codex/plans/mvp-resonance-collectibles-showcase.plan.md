# Plan: 可玩产品原型的共鸣合成、收藏品检视与展示柜

> **已被新计划替代**：用户于 2026-07-30 将机制扩展为“四岛配方、80% 通用承载器／20% 独特藏品、夜间记忆空间＋藏品展示柜”。当前活动计划见 [`island-collectibles-memory-spaces.plan.md`](island-collectibles-memory-spaces.plan.md)；本文件只保留上一阶段的实施依据。

**复杂度**：大（单个原型中的跨状态机、资源、3D 交互与验证改造）
**当前阶段**：建议契约待用户确认；确认前不修改实现文件

## 概述

在 `prototype/temple-mvp/` 的现有昼夜循环上增加一条可重复、可观察的收藏闭环：玩家白天与上贡者进行非空对话获得记忆能量，夜晚回收供品，消耗“1 件供品 + 1 点记忆能量”完成一次共鸣合成，得到可长期保留的收藏品。收藏品可以进入独立 3D 检视界面进行 360°旋转／缩放，也可以放入庙内展示柜并再次取下或检视。

## 需求复述

- **目标**：让供品与能量成为两种独立资源；收藏品不能再只靠供品生成；完成收藏品的 360°检视和展示柜陈列。
- **项目事实**：
  - 最新权威术语是“记忆能量”，定义为从白天真实对话获得、在夜晚共鸣时消耗的代币。
  - 最新权威角色术语是“上贡者”。
  - 当前 MVP 对话只回显文字、加工只消耗供品、唱片在进入新一天时被清空。
- **建议默认（待确认）**：
  - UI 使用正式术语“记忆能量”，并以“共鸣代币”解释，不把全项目资源重命名为“共鸣能量”。
  - MVP 中每次提交一条非空回应获得 `1` 点记忆能量；空回应不奖励。暂不模拟画像一致性和探索加成。
  - 一次共鸣合成固定消耗 `1` 件供品 + `1` 点记忆能量，产出一件“记忆唱片”收藏品。
  - 收藏品和展示柜跨昼夜保留，但刷新页面后重置；暂不引入账号、存档或 `localStorage`。
  - 展示柜先做 3 个可见陈列位；收藏品可放入、取下、点击检视。
  - 360°检视采用独立覆盖层：鼠标／触摸拖拽旋转、滚轮／双指缩放、自动慢转、重置和关闭。
- **明确非目标（待确认）**：
  - 不接真实 AI，不实现对话质量评分、画像线索和推荐算法。
  - 不做稀有度、掉落概率、交易、磨损、皮肤市场等 CSGO 经济系统。
  - 不引入外部美术资产或联网依赖。
  - 本任务不迁移或重命名 `prototype/temple-mvp/`，不改造 `project/` 旧 Vite 骨架；当前实现继续作为活动可玩产品原型演进，正式工程去向另行定案。

## 任务拆解

### M1：建立可测试的资源规则

- **做什么**：
  1. 先写 `node:test` RED 用例；
  2. 新建规则模块，定义能量奖励、合成判定和原子资源扣除；
  3. 确认错误路径不会误扣供品或能量。
- **预期 RED**：测试因 `game-rules.js` 不存在或缺少 `awardDialogueEnergy` / `synthesizeCollectible` 而失败。
- **验证**：`node --test "prototype/temple-mvp/tests/game-rules.test.cjs"`

### M2：把记忆能量接入白天对话与 HUD

- **做什么**：
  1. 增加独立能量计数显示；
  2. 非空回应结算 1 点，空回应不奖励；
  3. 对话反馈明确说明获得能量；
  4. 新一天不清除能量和收藏品。
- **模仿**：集中 `state`、DOM 缓存、`updateHud()` 和 `updateHint()`。
- **验证**：静态规则测试 + 浏览器中分别提交非空／空回应，核对计数变化。

### M3：改造夜晚共鸣合成

- **做什么**：
  1. 供品保持独立物品；
  2. 选择供品并点击宠物装置时，同时检查能量；
  3. 缺任一资源时显示原因且不消耗；
  4. 条件满足时立即保留扣除结果，完成进度后生成带唯一 ID 的记忆唱片收藏品。
- **模仿**：现有 `startProcessing()` / `finishProcessing()` 和拾取物流程。
- **验证**：规则测试覆盖四种资源组合；浏览器检查加工前后 HUD、物品栏和产物。

### M4：实现收藏品 360°检视

- **做什么**：
  1. 新增全屏／大面积检视覆盖层和独立 Three.js 场景；
  2. 从物品栏或展示柜点击收藏品进入检视；
  3. 支持拖拽 360°旋转、滚轮／触摸缩放、自动慢转、重置、关闭；
  4. 世界主场景在检视期间不响应点击。
- **模仿**：现有 renderer、材质和输入事件风格；检视渲染使用同一颜色配置。
- **验证**：真实浏览器拖拽至少一整圈、缩放、重置和关闭；检查控制台无新增 error。

### M5：实现庙内展示柜

- **做什么**：
  1. 在固定镜头可见区域创建与当前 toon 风格一致的柜体和 3 个槽位；
  2. 物品栏选择收藏品后点击空槽完成陈列；
  3. 点击柜中收藏品打开检视；检视界面提供“收回保管处”；
  4. 陈列数据跨昼夜保留，且不允许同一收藏品重复占位。
- **模仿**：`makeToon()`、`userData.onClick`、raycast 和状态驱动提示。
- **验证**：摆入、检视、收回、换日后仍在四条浏览器路径。

### M6：兼容性、文档与记录

- **做什么**：
  1. 回归白天刷怪、昼夜切换、供品回收、宠物变形、倍速和音频；
  2. 更新 README；
  3. 同步 `记录/`；
  4. 差异检查，确保没有触碰正式 `project/` 或引入网络依赖。
- **验证**：
  - `node --test "prototype/temple-mvp/tests/game-rules.test.cjs"`
  - PowerShell 启动本地静态服务器后做真实浏览器 smoke；
  - 检查浏览器控制台；
  - `git diff --check`
  - `git status --short`

## 风险

| 风险 | 概率／影响 | 缓解 |
|---|---|---|
| “共鸣能量”与正式“记忆能量”形成并行货币 | 中／高 | UI 默认沿用“记忆能量（共鸣代币）”；若用户明确决定改名，再同步设计权威和记录。 |
| 930 行单文件继续膨胀 | 高／中 | 本轮先抽出纯规则模块；后续继续演进前需要安排可维护性重构，不能长期把全部功能堆入单文件。 |
| 固定机位看不清展示柜 | 中／高 | 先用视锥和真实截图校位；柜中物体提供检视覆盖层作为可靠入口。 |
| 指针拖拽与世界点击冲突 | 中／中 | 检视状态独占输入，移动阈值区分拖拽与点击。 |
| 新一天清理逻辑误删收藏品 | 中／高 | 资源规则测试 + 浏览器跨昼夜回归，清理只作用于临时供品／加工状态。 |
| 仅靠静态检查无法证明 3D 交互可用 | 高／高 | 必做真实浏览器视觉与交互验证；若准备引入独立 reviewer，先走风险分流。 |
