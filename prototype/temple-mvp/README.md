# 庙宇供奉 · Temple MVP（Three.js 原型）

> Flawed AI（神像供奉 AI 艺术教育游戏）第一版可玩原型。
> 你扮演供奉于庙中的**神像（诗人的化身）**：白天石像开门收贡、夜晚化灵体指挥**宠物**把供品加工成作品。
> 本版只求「核心机制跑通」，美术用占位几何体，但命中指定的 cel-shaded 东方治愈基调。

---

## ▶ 启动方式（必读）

**双击 `index.html` 即可打开，无需服务器、无需联网。** 首屏有开场说明卡，点「▶ 进入庙宇」开始。

- 也可把**整个文件夹拖到 [Netlify Drop](https://app.netlify.com/drop)** 托管成公开链接，发给团队/审核即开即玩。
- 或用静态服务器托管（效果相同）：`cd prototype/temple-mvp && python -m http.server`，浏览器开 <http://localhost:8000>。

**完全本地、零网络依赖**：
- Three.js **r160** 用本目录的 `three.min.js`（UMD 全局版）经普通 `<script>` 引入——`file://` 下也能加载（不像 ESM importmap 会被 CORS 拦）。
- 零外部美术 / 音频素材：gradientMap 内联生成、音效用 WebAudio 合成。

> 控制台会有**一句** `three.min.js` 的 "deprecated" **warning**——属预期、无害（想消掉可删 `three.min.js` 开头那行 `console.warn(...)`）。除此之外应**无 error**。

## 🧭 快速验收路线（约 3 分钟）

1. 点「进入庙宇」。右上角点 **20×**（把 20min 白天压成约 1 分钟）。
2. 观察上贡者**成群、错落**走入 → 停留 → 走出；**点击任一上贡者** → 其供品落入**绿色区** + 镜头拉近 + 弹对话框，输入文字回车 → 镜头归位。
3. 点 **⏭ 跳过白天** → 进入**夜晚**：庙门合上、室内灯亮。
4. **点击神像** → 化为青绿灵体（C1）。
5. **点击绿色区供品**或**点击宠物**回收 → 右下**物品栏**出现「供品」。
6. **点击宠物（狗）** → 变**面包机**；在物品栏**点一件供品选中** → **点面包机**投料 → 进度条约 50s（20× 下约 2.5s）→ 产出**唱片**。
7. **点击漂浮的唱片**拾取 → **点面包机** → 变**唱片机** → **点唱片机播放**（转盘加速旋转 + 顶部「♪ 正在播放」+ 合成音）。
8. 点 **🌅 进入第 N 天** → 回到白天，循环验证。

> 左下角始终有「当前该点什么」的动态提示，照着点即可走完整链路。

## ✅ 验收清单逐条对应（实现位置 / 触发方式）

代码集中在单个 `index.html` 的 `<script type="module">`，按 `§A`–`§P` 分段并在注释标注验收 ID。

### A · 场景与昼夜
| 项 | 实现 | 触发 / 观察 |
|----|------|------|
| A1 长方体庙、一面可开合、开口够大 | `§E` 庙宇墙体 + `door`（宽 12 的陶土门，向上滑出=开） | 直接可见；门两侧留门柱使开口居中 |
| A2 白天开门外光 / 夜晚合门室内灯 | `§C` 灯光（`sun` 外部光 / `interior` 室内暖灯），`endDay`/`startNewDay` 切换 | 切到夜晚即见门合、外光灭、暖灯亮 |
| A3 昼夜可切换、白天两种结束方式 | `endDay()`（窗口耗尽 or 跳过）/ `startNewDay()` | 等倒计时归零 **或** 按跳过键 |
| A4 可见 HUD（阶段/天数/倒计时/倍速） | `§F`+`§N` 顶部 HUD（`#hud`） | 屏幕顶部常驻，无需读代码 |

### B · 白天 · 上贡者与供奉
| 项 | 实现 | 触发 / 观察 |
|----|------|------|
| B1 成群（2~3）到来、错落站位、节奏具名常量 | `spawnGroup()`；`TUNING.SPAWN_MIN/MAX`(30~45s)、`GROUP_MIN/MAX` | 多人一组扇形散开，非排队 |
| B2 每人手持一件供品 | `spawnOfferer()` 中 `makeOfferingMesh()` 挂在手部 | 走来时手上有占位几何 |
| B3 走入≈5s / 停留≈10s / 走出≈5s | `updateOfferer()` 状态机；`TUNING.OFFERER_WALK_IN/STAY/WALK_OUT` | 观察单个上贡者节奏 |
| B4 点击上贡者→供品入绿色区 | `onOffererClick()`→`dropOffering()` | 点击即落入绿色区 |
| B5 点击→镜头拉近+对话框+可打字输入框（只显示不处理） | `onOffererClick`→`flyCamera`→`openDialogue`→`submitReply`（仅回显） | 点击后下方输入框，回车回显，**不接 AI** |
| B6 流程可重复、白天窗口≈20min | 循环刷新；`TUNING.DAY_WINDOW=1200s`，可跳过/倍速压缩 | HUD 倒计时；多组反复 |
| B7 跳过键：不互动也自动收贡、跳过不弹对话 | `endDay(true)`；未互动者在停留末自动 `dropOffering` | 按「⏭ 跳过白天」 |
| B8 点击才有对话，不点只完成供奉 | 对话仅在 `onOffererClick`；自动落供在 `updateOfferer` | 不点也会留下供品 |

### C · 夜晚 · 回收与加工
| 项 | 实现 | 触发 / 观察 |
|----|------|------|
| C1 合门进夜晚、神像可切灵体 | `endDay()` 合门；`toggleSpirit()`（点神像） | 点神像变青绿半透辉光 |
| C2 玩家/宠物拾取绿色区供品入物品栏 | `collectOffering()`（点供品）/ `collectAll()`（点宠物） | 供品消失、物品栏出现 |
| C3 点宠物（狗）→变面包机 | `onPetClick()`→`setPetForm('toaster')` | 回收完后点狗变面包机 |
| C4 投料→约50s（可见进度）→产出唱片 | `startProcessing()`/`finishProcessing()`；`TUNING.NIGHT_PROCESS=50s`；`#process` 进度条 | 选材料→点面包机→看进度条 |
| C5 拾取唱片进物品栏 | `spawnRecordPickup()`/`pickupRecord()` | 点漂浮唱片 |
| C6 再点→变唱片机→可见+可听播放 | `setPetForm('player')`→`playRecord()`（WebAudio oscillator） | 转盘旋转+「♪」+合成音 |
| C7 宠物三态机：狗↔面包机↔唱片机，状态可观察 | `setPetForm()` 切换 `dogForm/toasterForm/playerForm` 可见性 | 点击在三形态间推进 |

### 5/6 · 时间常量与倍速
- 所有时长集中在 `TUNING`（`§B`），数值与任务 §5 基准一致。
- 倍速 **1× / 5× / 20×**（`§F` 按钮，`data-spd`），只缩放游戏内计时（`dt = dtReal * speed`），默认 1×。

### 皮肤化架构（任务 §2 必做）
- 所有视觉参数集中在 `assetConfig`（`§A`）：`colors`（色盘）+ `textures`（贴图路径，当前全空）+ `useTextures` 总开关。
- 渲染层只经 `makeToon()`/`resolveMap()` 读取它；贴图留空→回退纯色占位。
- 换肤：往 `assets/` 丢图 + 在 `assetConfig.textures` 填路径 + `useTextures:true`，**不改任何渲染逻辑**。详见 `assets/README.md`。

### 视觉基调（任务 §3）
- 卡通渲染：`MeshToonMaterial` + 内联 `DataTexture` 生成的 4 阶 `gradientMap`（`makeGradientMap`）。
- 手绘墨线描边：反向壳（BackSide + 略放大），深炭灰 `#2E3A38`（`makeToon` 的 outline）。
- 去饱和东方色盘：色值锚点全部落在 `assetConfig.colors`，占位几何严格用该色盘，无刺眼原色。

## ⬜ 本版明确未做（不假装做了）

- **AI 对话**：上贡者提问由 AI 动态生成、对话提升「信仰值」、回应质量换更好供品 —— **未做**。B5 的输入框只接受并回显文字，不接任何 AI、不做处理。
- **满意度 / 信仰值系统**及其驱动的产出升级（积攒式调养） —— **未做**。故每位上贡者恒定留下其手持那一件供品。
- **宠物「有缺陷的 AI」讲解作品** —— **未做**。
- **付费 API / 信仰值等高级机制** —— 全部未做（任务要求本版不做）。

## 📌 实现假设（不确定处的取舍，向源规格靠拢且不破坏核心循环）

1. **夜晚结束方式**：源规格未明说夜晚如何收尾，本版加一个「🌅 进入第 N 天」按钮（HUD 行动键在夜晚的形态）推进新一天，便于循环演示。
2. **宠物点击语义消歧**：夜晚点宠物——绿色区**还有供品时**=帮忙拾取（C2）；**供品已清空后**=在三态间推进（狗→面包机→唱片机）。面包机态下「选中材料再点面包机」=投料加工；无材料且已有唱片时点面包机=切唱片机。已在左下提示与本文档说明，确保可观察。
3. **每日清空产出**：`startNewDay` 会清空上一夜的物品栏与残留供品，使「供奉→转化→再创作」整链可被反复、干净地演示（非数值存档版本）。
4. **材料种类**：按源规格「初版最小链路」只做一种材料（占位「供品」），一种成品（唱片）。
5. **灵体切换**为可选步骤（点神像），不阻塞加工链路；不点也能继续回收加工。
6. **随机性**：用自带的轻量伪随机（避免环境差异），故每次刷新的上贡者外观/站位序列固定，不影响机制演示。
7. **镜头**：「视角从神像出发」**不**理解为把相机放在神像眼睛处（那样反而看不见神像本体），而是**固定的微缩 diorama 高位斜俯过肩三人称**——神像作为**可见的前景锚点**，与宠物狗、绿色区、庙门开口（及进出的上贡者）**同屏可见**。为此采用 diorama 切面（`DIORAMA_CUTAWAY`）隐藏会挡视线的后墙/天花板/屋顶，相机退到后墙外后上方俯瞰；左右侧墙、地板、门柱、庙门保留以维持封闭感。仍是**单一固定机位**：点击上贡者时脚本式推近、本轮结束自动归位，**不可自由操控**。机位常量集中在 `CAM_HOME` 与相机 FOV 两处，便于微调。
