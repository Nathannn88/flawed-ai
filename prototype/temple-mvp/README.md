# 《诗人与岛》庙宇供奉 · 持续可玩产品原型

> 当前活动实现位于 `prototype/temple-mvp/`。目录名保留历史痕迹，但这里已经不是一次性 MVP，而是继续演进和验收的可玩产品原型。
>
> 当前纵向切片：寺庙按已确认结构图展开为**祈愿厅、处理室与陈列室**。白天玩家可在神像及三名房间管理员的具身视角间切换，并通过上供者对话获得**记忆能量**；夜晚独立灵体可自由穿行三房间，回收并选择两件材料完成共鸣。每次结果都是“载体＋艺术品＋材料来历”绑定的**记忆藏品**，可归还材料、珍藏到记忆空间，或走到陈列室策展进三槽展示柜。

## 启动与验证

双击 `index.html` 即可运行，无需服务器或联网。也可以用本地静态服务器：

```powershell
cd prototype/temple-mvp
python -m http.server 8000
```

自动测试：

```powershell
node --test prototype/temple-mvp/tests/*.test.cjs
```

本原型使用本地 Three.js r160 UMD 文件、代码生成的 toon 几何和 WebAudio 合成音。控制台中 Three.js 自带的一条 deprecated warning 属于已知提示；除此之外不应出现 error。

涉及 UI、3D、模型、构图或动效的交付，还必须执行 [`视觉与交互验收规范.md`](视觉与交互验收规范.md)。自动测试不能替代真实页面截图、动态证据和画风分析。

## 五分钟体验路线

1. 点击“进入庙宇”，可将速度切到 `20×`。
2. 使用左上视角条依次切换神像、祈愿厅管理员、处理室管理员和陈列室管理员；HUD 会持续显示当前身份与房间。白天是预设具身视角，不是自由漫游。
3. 回到神像视角，等待至少两位上供者进入。点击上供者，提交非空回应；每次有效回应固定获得 1 点记忆能量，空回应不奖励。
4. 点击“跳过白天”进入夜晚。未离场者会留下手持供品，庙门合上、三名管理员退场、宠物出现，独立灵体自动从神像旁显现。
5. 用 `WASD`／方向键或点击地面移动灵体。先在祈愿厅靠近供品逐件回收；材料栏显示具体材料名。宠物不再跨房间代取。
6. 沿中轴门洞走到处理室，靠近并点击宠物使其变为共鸣装置；在材料栏选择两件材料，再点击装置。
7. 资源合法时原子消耗 2 件材料和 1 点记忆能量，约 50 游戏秒后出现无倒计时的艺术记忆。
8. 在结果卡中完整观看艺术品与材料来历：
   - 向左拖、按左方向键或点左按钮：归还两件材料，不返记忆能量；
   - 向右拖、按右方向键或点右按钮：把完整记忆藏品放入记忆空间。
9. 点击结果卡右上“360°观察载体”，可在决定前检查模型；拖拽旋转、滚轮／双指缩放，关闭后回到原结果。
10. 夜晚点击顶部“记忆空间”，可查看随收藏动态扩展的网格，并按载体类型、陈列状态或艺术类别筛选，按获得顺序或标题排序。
11. 打开任一已珍藏藏品进行 360°检视，点“选择展示位”，关闭覆盖层后继续把灵体走到陈列室；靠近并点击展示柜空槽。藏品仍保留在记忆空间，展示柜只保存策展引用。
12. 从展示柜点击藏品可再次检视并移出展示柜。音乐类艺术记忆存在时，处理室的共鸣装置还可切换为唱片机播放对应合成音。
13. 进入下一天，确认材料、记忆能量、记忆藏品与展示柜陈列保持；刷新页面后全部重置。

左下角提示会根据阶段、资源和当前选择持续给出下一步。

## 当前核心规则

### 两种资源

- **供品材料**：由四个未来上供岛提供，当前以八种具体材料进入材料栏。
- **记忆能量**：来自与上供者的非空对话，和材料分开计数。
- 每次有效共鸣固定需要 `2 件材料 + 1 点记忆能量`。
- 缺材料、材料实例失效或能量不足时拒绝开始，资源保持不变。

### 四岛、材料与配方

| 岛屿方向 | 材料公式 | 20% 配方奇珍 |
|---|---|---|
| 视觉 | 虹膜浆果＋镜盐 | 万花筒果实 |
| 表演 | 麦穗面包＋回声贝 | 面包唱片 |
| 文学 | 墨籽＋线叶 | 翻页种子书 |
| 设计与应用 | 榫木＋釉土 | 榫卯月灯 |

材料顺序不影响配方识别。

- 命中配方：`roll < 0.2` 生成对应配方奇珍，其他 80% 生成常规载体“无名记忆匣”。
- 未命中配方：稳定生成无名记忆匣，不会因为低随机值误出其他奇珍。
- 80%／20% 只区分**载体形态**，不区分艺术价值。两个分支都绑定艺术品、都能珍藏、重开、360°检视和陈列。

### 艺术内容

当前内容目录含十二份明确标注为虚构原型的艺术品：

- 行为艺术 2
- 建筑艺术 2
- 音乐 2
- 图画 2
- 小说 2
- 设计／工艺 2

抽取优先尚未见过的作品；当十二份都经历过后再允许重复。当前文字和声音用于验证收藏感知循环，不代表正式艺术授权内容。

### 归还与珍藏

- 结果显现后没有强制倒计时，玩家可先阅读并检查载体。
- 归还会恢复本次两件原材料，但不会恢复已经消耗的记忆能量，避免无成本无限重抽。
- 珍藏会把载体、艺术品、材料来历、配方与岛屿来源作为一个不可拆分的记忆藏品写入记忆空间。
- 同一个待决结果只能最终处理一次；快速重复点击不会重复返料或重复入库。

### 记忆空间与展示柜

- 记忆空间只在夜晚开放。
- 逻辑容量不设固定上限，UI 网格随收藏继续增长；不是六卡片或装备栏。
- `memoryItems` 是藏品唯一所有权来源。
- 三槽展示柜只保存 `memoryItemId` 引用；策展不会把藏品从记忆空间移走。
- 同一藏品换槽时旧槽自动清除；已占满时必须先移出一件藏品。
- 记忆空间是夜间内在背包，可从任何房间打开；展示柜是陈列室实体，点击空槽、已陈列模型或收回藏品都要求灵体先抵达并靠近。

### 寺庙空间与昼夜具身

- 祈愿厅：神像、庙门、上供者和供品区；
- 处理室：夜间宠物、材料处理与共鸣装置；
- 陈列室：三槽实体展示柜；
- 两道宽门洞和浅台阶连接三房间；分界处只有中轴通道可穿越，灵体不会直接穿过两侧墙柱；
- 白天可选神像、祈愿厅管理员、处理室管理员、陈列室管理员四个预设具身视角；
- 夜晚只有玩家的独立灵体可移动，镜头平滑跟随，HUD 根据纵深位置更新当前房间；
- 对话、共鸣结果、记忆空间和 360°检视打开时，世界移动暂停，避免覆盖层与行走输入冲突。

## 实现分层

| 文件 | 职责 |
|---|---|
| `content-catalog.js` | 四岛、八材料、四配方、五载体和十二艺术品的唯一运行时内容目录 |
| `game-rules.js` | 对话奖励、共鸣原子性、80/20、艺术优先抽取、归还／珍藏和展示柜引用纯规则 |
| `index.html` | 三房间场景、白天具身视角、夜间灵体移动、上供者、材料 UI、共鸣过程、甄选手势、记忆空间、3D 检视和展示柜 |
| `tests/content-catalog.test.cjs` | 内容数量、关系与类别覆盖 |
| `tests/game-rules.test.cjs` | 资源、概率边界、幂等、返料、入库和柜位规则 |
| `tests/index-behavior.test.cjs` | 覆盖层输入优先级、可编辑目标隔离和两道门洞连续碰撞行为 |
| `tests/index-contract.test.cjs` | 本地依赖、页面状态、三房间、管理员视角、灵体移动、距离门禁、手势、背包、检视与五模型契约 |

页面仍支持 `file://` 双击运行：

```text
index.html
  → content-catalog.js
  → game-rules.js
  → Three.js 场景与 UI 状态机
```

运行时代码不读取仓库 `design/`；设计源素材需要复制或转换到当前原型的 `assets/` 后才能使用。

## 3D 与视觉实现

当前五类载体都由同一模型工厂创建，并同时用于展示柜和独立检视舞台：

- 无名记忆匣：标准盒体、盖板、缝隙光与共鸣核心；
- 万花筒果实：镜片花瓣、错位色环和种蒂；
- 面包唱片：烘烤色唱片、沟槽、回声贝唱臂；
- 翻页种子书：封面、页块、墨籽书脊与悬浮线叶；
- 榫卯月灯：无钉框架、显露接头与发光釉土灯胆。

所有占位模型延续现有的去饱和东方色盘、四阶 toon 光照和反向壳墨线。它们已经具备可辨识的正侧背轮廓，但仍属于正式建模前的产品级形体原型。

检视舞台支持：

- 鼠标／单指拖拽连续旋转；
- 滚轮／双指缩放；
- 缩放上下限；
- 松手自动慢转；
- 重置与关闭；
- 待决结果和已珍藏结果共用同一模型定义。

## 已知验收边界

自动测试和脚本解析只能证明结构、纯规则与基本接线成立。以下结论必须来自可用的真实浏览器：

- 场景和覆盖层有没有遮挡；
- 五类模型是否裁切、穿模或旋转中心漂移；
- 手势阈值、缩放边界和动态反馈是否自然；
- 记忆网格密度、文字对比和移动端布局是否可读；
- 三房间在各自白天视角和夜间跟随镜头中的大小、光照、门洞遮挡与点击命中；
- 管理员轮廓、灵体移动速度、门洞碰撞、房间切换反馈和跟随镜头是否自然；
- 新模型与庙宇原有 toon 画风是否一致。

如果浏览器控制、截图或录屏不可用，必须将这些项目标记为 `BLOCKED`，不能用 DOM 搜索、坐标投影或自动测试冒充视觉通过。
