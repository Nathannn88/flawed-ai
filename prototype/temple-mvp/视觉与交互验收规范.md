# 《诗人与岛》可玩产品原型 · 视觉与交互验收规范

> 适用范围：`prototype/temple-mvp/` 的 UI、3D 场景、模型、材质、构图、动效与交互反馈。
>
> 核心原则：**逻辑测试证明“能运行”，截图与录屏证明“玩家实际看到的体验是否成立”。两者缺一不可。**

## 一、完成定义

一次涉及可见界面的交付，只有同时满足以下条件才可标记完成：

1. 自动测试、语法／构建检查和最相关负面路径通过；
2. 使用真实浏览器走完本次新增路径和最相关回归路径；
3. 主 agent 主动截取代表状态，并亲眼查看原图；
4. 涉及旋转、变形、镜头、昼夜或连续反馈时，优先录制短屏；宿主没有录屏能力时，至少截取起点／过程／终点连续状态；
5. 对画风与交互质量逐项分析，不以“没有报错”“元素在视锥内”代替视觉判断；
6. 发现会影响焦点、理解或风格的问题时先修复，再做至多一轮定向复检；
7. 浏览器、截图或录屏能力不可用时，结论写 `BLOCKED`，不得宣布视觉通过。

## 二、固定证据集

### 每轮至少截图

| 编号 | 状态 | 必查内容 |
|---|---|---|
| S1A | 白天神像／祈愿厅视角 | 神像、上供者、绿色区、庙门和祈愿厅管理员是否形成清楚层级 |
| S1B | 白天处理室管理员视角 | 管理员、处理地标与宠物夜间位置是否能建立空间预期 |
| S1C | 白天陈列室管理员视角 | 管理员、展示柜三槽和通往处理室的门洞是否可辨 |
| S2 | 对话与能量反馈 | 对话框是否遮挡主体；获得能量的因果是否一眼可懂 |
| S3 | 夜晚灵体与双材料准备 | 独立灵体、当前房间、移动提示、夜色、两件选中材料、记忆能量和下一步提示是否可辨 |
| S4 | 共鸣加工与艺术显现 | 资源扣除、进度、无倒计时结果卡、载体／艺术／材料来历是否形成清楚层级 |
| S5 | 左归还／右珍藏 | 拖拽阈值、方向提示、等价按钮和资源结果是否一眼可懂 |
| S6 | 夜间记忆空间 | 多格密度、筛选排序、常规／奇珍和艺术类别是否可读，收藏增长是否像背包而非六格装备 |
| S7 | 五类载体检视正面／侧面／背面 | 模型轮廓、材质、深度、旋转中心和缩放边界 |
| S8 | 展示柜空／单件／满柜 | 空位暗示、柜体遮挡、收藏品大小、满柜反馈和主场景构图 |
| S9 | 跨昼夜后的背包与陈列 | 材料、能量、藏品和策展引用是否保持；新一天是否出现叠物或残留 |

### 动态表现优先录屏

建议录制 30–60 秒短屏，至少覆盖：

1. 非空回应 → 能量增加 → 进入夜晚；
2. 白天依次切换神像及三名管理员视角，观察身份／房间 HUD 与镜头过渡；
3. 夜晚灵体从祈愿厅回收供品，经中轴门洞走到处理室，再走到陈列室；检查跟随镜头、墙柱碰撞和房间提示；
4. 选择两件材料 → 缺能量失败或成功原子扣除 → 艺术显现；
5. 左拖归还与右拖珍藏各走一遍，并对照材料和能量变化；
6. 常规载体及四件奇珍各完整旋转一周、缩放、重置；
7. 记忆空间筛选、排序、打开详情；
8. 选择展示位、走到陈列室、摆入、点击检视、移出与满柜反馈；
9. 昼夜切换时的灯光、门、管理员、宠物／装置、灵体、背包和陈列保持。

若当前宿主只能截图，使用连续截图替代并明确标注“未取得视频证据”，不能声称已经检查动画流畅度。

## 三、视觉分析维度

每轮报告都必须回答以下问题：

| 维度 | 判定问题 | 常见失败 |
|---|---|---|
| 构图与焦点 | 玩家第一眼看哪里？当前任务对象是否是最清楚的视觉焦点？ | 展示柜贴边、主体被 HUD 覆盖、同时多个高亮争抢注意 |
| 遮挡与空间 | 模型、墙体、玻璃、UI 是否挡住关键对象或点击热区？ | 柜背挡收藏品、透明玻璃拦截 raycast、提示覆盖场景 |
| 空间导航 | 玩家能否从门洞、地标、镜头与房间提示判断当前位置和去向？ | 三房间像重复走廊、门柱挡路、镜头穿墙、点击目的地不可达 |
| 视觉层级 | 主操作、状态、说明和装饰是否有明确优先级？ | 所有面板同等重量、资源数值不突出、按钮像标签 |
| 画风一致性 | 新模型、柜体、检视舞台是否延续色盘、描边、材质和形体语言？ | 柜体过于写实、检视舞台像另一个游戏、默认原色突兀 |
| 色彩与光照 | 昼夜对比、收藏品颜色和文字对比是否清楚且舒适？ | 夜间黑成一片、发光过曝、文字与背景对比不足 |
| 可读性 | 字号、行长、提示时长和屏幕位置是否便于理解？ | 信息闪过太快、移动端溢出、术语不一致 |
| 交互暗示 | 玩家不用读代码能否知道可点、可拖、可缩放、可摆放？ | 空槽无提示、收藏品不像可点击、拖拽后误触主场景 |
| 动效与反馈 | 操作是否有及时、因果明确、不过度的动态反馈？ | 扣资源无反馈、加工像卡死、旋转中心漂移、切换突兀 |
| 产品语义 | 画面表达的是“有来历的记忆收藏”，还是普通合成掉落物？ | 只强调数值和稀有度，来源与共鸣关系不可见 |

## 四、当前收藏功能验收条件

- **AC-V1**：白天非空回应后的能量增加在截图中清楚可见；空回应不增加。
- **AC-V2**：夜晚不足两件合法材料或缺能量时，失败反馈可见且资源不变化；成功时两材料与一点能量同时扣除。
- **AC-V3**：艺术显现没有强制倒计时；载体、艺术内容和材料来历层级清楚，待决载体可进入 360°检视。
- **AC-V4**：左拖／左键归还两件材料但不返能量；右拖／右键把完整藏品写入记忆空间；按钮提供同等能力。
- **AC-V5**：记忆空间仅在夜晚开放，网格可持续增长；筛选、排序、详情和陈列状态在桌面与代表移动视口可读。
- **AC-V6**：无名记忆匣、万花筒果实、面包唱片、翻页种子书和榫卯月灯都能被正侧背观察，不裁切、不穿模；鼠标／触摸拖拽、滚轮／双指缩放和重置有效。
- **AC-V7**：三个展示位在代表桌面视口中全部可见、可点且不被 HUD／材料栏遮挡。
- **AC-V8**：摆入、再次检视、移出和满柜失败路径都有可理解反馈；策展后藏品仍保留在记忆空间，同一藏品不能重复占位。
- **AC-V9**：跨昼夜后材料、能量、记忆藏品与陈列保持，场景没有重复模型、残影或旧进度条。
- **AC-V10**：除 Three.js 已知 deprecated warning 外，控制台没有新增 error。
- **AC-V11**：五类载体、记忆空间、结果卡和展示柜延续现有去饱和东方 toon 方向；常规载体不能被视觉处理成安慰奖，明显占位感或风格冲突必须记录。
- **AC-V12**：神像和三名管理员的四个白天视角均能清楚辨认当前身份、所在房间和关键实体；切换过程不穿墙、不突然翻转。
- **AC-V13**：夜晚石像保留、独立灵体可见；WASD／方向键和点击地面都能连续移动，覆盖层打开时不会误走。
- **AC-V14**：祈愿厅 → 处理室 → 陈列室的门洞、台阶、地标与 HUD 能持续提供方向感；墙柱不可穿过，房间切换提示与实际位置一致。
- **AC-V15**：供品、宠物和展示柜的距离门禁有效，失败反馈能指出应前往的房间；已陈列模型不能被跨房间隔空打开。

## 五、风险自适应分流

### 验证分流清单

- **任务类型**：持续可玩原型的功能、视觉与交互联合验收
- **风险等级**：`L2`
- **风险依据**：跨状态机与双 Three.js 场景，修改可回滚；逻辑错误有自动测试，但遮挡、raycast、手感和画风问题较隐蔽
- **已有证据**：内容、资源规则、页面契约与行为测试 33/33；内联脚本解析；双材料、80/20、幂等甄选、夜间背包、五模型、三槽 ID 引用、三房间、四视角、移动入口、镜头房间归属、距离门禁、覆盖层输入优先级与两道门洞连续碰撞均有机械证据
- **已覆盖**：内容数量、资源原子性、概率边界、返料／入库、脚本依赖、三房间标识、视角入口、移动输入、距离门禁、甄选输入、背包结构、检视输入和三槽结构
- **未覆盖**：真实渲染、实际点击命中、灵体移动手感、门洞碰撞体感、跟随镜头、拖拽阈值、动画流畅度、构图、遮挡、移动端密度和画风一致性
- **选择模式**：`standard`
- **选择的 reviewer lanes**：首轮由主 agent 执行 `functional + visual self-check`；出现仍会改变产物或裁定的主观争议时，最多追加 1 个独立 `functional/consistency` reviewer
- **跳过 lanes**：`security`（无认证、权限、支付或外部输入面）；独立 `negative` reviewer 暂跳过，失败路径先由主 agent 实测
- **reviewer 数量预算**：首轮 `0`，残余风险成立时最多 `1`
- **总时间预算**：首轮 10 分钟；定向复检最多 5 分钟
- **最大验证轮数**：实现后 1 轮全面视觉验收；CRITICAL/HIGH 修复后最多 1 轮定向复检
- **本轮预期新增信息**：真实画面是否暴露遮挡、点击失效、风格割裂或反馈不清
- **停止条件**：一轮没有发现会改变产物或 verdict 的实质问题，或下一轮只会重复已有证据

## 六、证据保存与报告

临时证据放在工作区：

```text
tmp/visual-acceptance/<YYYYMMDD-HHMM>/
├── screenshots/
├── recordings/
├── console.txt
└── report.md
```

使用前确认目录位于工作区内。证据可以在任务结束后按需要清理；项目长期记录只写结论和关键文件链接，不复制整批截图或视频。

`report.md` 至少包含：

1. 当前 commit／工作树标识与视口；
2. 实际执行路径；
3. 截图／录屏文件清单；
4. 上述九项视觉维度的观察；
5. 每条 AC-V 的 PASS／FAIL／BLOCKED 与证据；
6. 修复项、残余风险和最终 verdict；
7. 若未录屏，明确写出哪些动态风险没有被覆盖。
