# 《诗人与岛》设计与美术源

> `design/` 是产品设计文稿和美术源资产的唯一活动总览。Obsidian、Google Drive、原型和代码目录都不是设计 source of truth。
> 本文件递归适用于 `design/` 全部子目录；子板块不再各自复制 `AGENTS.md`／`CLAUDE.md`，避免目录调整后产生漂移。

## 开工顺序

1. 先读 `设计资料索引.md`；
2. 再读 `00-项目核心/最高设计权威.md` 的相关章节和第十一节术语表；
3. 按任务读取对应分项文稿或素材索引；
4. 检查 `../记录/进度.md` 中的开放问题、活动原型状态和未完成验收。

## 设计更新流程

用户会把新资料放进仓库并告诉 Agent“更新了”或给出路径。收到后：

1. 读取真实文件，不要求用户先整理成 Obsidian 笔记；
2. 拆分为正式决定、待验证提案、素材、开放问题和历史证据；
3. 与最高设计权威核对；新决定冲突时先报告并确认；
4. 形成影响清单；目标和授权明确时直接同步权威、分项文稿、索引和全部下游，只有改写最高权威、永久删除、法律口径或存在多种方向时才停下确认；
5. 更新 `../记录/进度.md`；人类拍板和本次产出分别以 `[决策]`、`[活动]` 写入 `../记录/决策与活动日志.md`；再全仓扫描旧路径、旧术语和悬空引用，按风险决定是否补一次独立一致性审查。

## 素材规则

- `design/40-美术素材/` 保存原始设计资产和最高质量源文件；归属或命名不确定时放入 `90-待整理/` 或 `40-美术素材/待确认/`；
- 代码不得直接引用 `design/`；运行素材复制／转换到当前 `../prototype/temple-mvp/assets/`，正式迁移后才改为 `../project/`，并在 `40-美术素材/素材索引.md` 登记源路径、运行时路径、处理方式和版本；
- 不覆盖旧源文件；新版本使用日期或版本号；
- 永久删除前先进入 `99-待删除审核/` 并取得用户确认。

## 协作与视觉传播

- 用户最新明确决定高于尚未更新的旧文稿；若新决定推翻旧阶段或设计假设，先重启诊断，再同步最高权威、分项文稿、索引、根规则、计划、记录和相关 skill，不用局部补丁掩盖冲突。
- 设计或素材变更若会影响 UI、3D 场景、模型、材质、构图、色彩、字体、动效或交互反馈，影响清单必须包含当前活动原型和 `../prototype/temple-mvp/视觉与交互验收规范.md`。
- 仅整理设计文稿时不强行启动浏览器；一旦变更已经落入运行时画面，交付前必须打开真实页面，主动截图并亲眼检查画风、构图、遮挡、层级、色彩、可读性和交互暗示。旋转、变形、昼夜切换等动态表现优先录屏，至少也要有连续截图。
- 浏览器、模型预览或录屏能力不可用时明确标记 `BLOCKED` 并写入进度；静态文件存在、DOM、坐标和自动测试不能代替视觉通过。
- 长任务持续记录已验证证据、当前阻塞和恢复入口；最终汇报区分 `PASS`、`BLOCKED` 与尚未验证。

- `.base`、`*MAP.md` 与子板块规则已永久退役，不把历史日志或 Git 中的同名文件恢复成活动导航；

- 两份规则必须保持业务语义一致，只允许宿主名称、调用语法和真实工具接口不同；
- 结构变化时更新 `设计资料索引.md` 和项目级 `my-design-sync` 配置；
- 历史决策日志只追加，不改写旧条目；待删除审核区只读，除非更新审核状态。
