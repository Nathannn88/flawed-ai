# 长任务里程碑计划

## 计划原则

- 一次只推进一个 `in_progress` 里程碑。
- 先写会失败的规则测试，再实现资源逻辑。
- 3D 交互必须用真实浏览器验证，不能用静态搜索代替。
- 计划变化同步到 `STATE.md`；契约变化先校准 `CHARTER.md`。

## Current Execution Order

1. M1 — 先同步最高设计权威和所有活动下游，冻结新口径。
2. M2 — 用失败测试锁定内容、概率、资源和甄选不变量。
3. M3 — 接入仪式与待决结果，打通左右选择。
4. M4 — 在稳定记忆藏品数据上实现背包、四模型和策展柜。
5. M5 — 原切片机械审计完成，视觉验收并入扩展范围。
6. M6 — 先同步空间、身份和移动权威口径。
7. M7 — 建立三房间寺庙与连通关系。
8. M8 — 接入管理员和白天具身视角切换。
9. M9 — 接入夜间灵体移动、跟随镜头与空间交互。
10. M10 — 全量回归并取得真实动态视觉证据。

## Risks

| 风险 | 概率/影响 | 早期信号 | 缓解与回滚 |
|---|---|---|---|
| 单文件状态互相污染 | high/medium | 换日误删或选中状态悬空 | 纯规则模块、稳定 ID、逐里程碑浏览器验证 |
| 检视拖拽触发世界点击 | medium/medium | 关闭检视后意外操作场景 | 检视状态独占输入并阻断主 raycast |
| 柜体不在固定机位视锥内 | medium/high | 首屏截图不可见或太小 | 先用坐标投影和截图校位 |
| 80% 常规结果仍像失败品 | medium/high | 玩家只追奇珍、常规不入库 | 两分支都绑定艺术、可检视和陈列；视觉证据检查价值层级 |
| 左拖形成免费重抽 | medium/high | 资源可无损循环 | 材料返还、能量不返，纯规则锁定幂等 |
| 背包与柜位双重所有权 | medium/high | 收回或替换后出现幽灵物品 | `memoryItems` 唯一所有权，柜位只存稳定 ID |
| 旧唱片音频链断裂 | medium/medium | 音乐艺术品无法播放 | 以艺术类型音频能力取代 `hasRecord` 兼容状态并纳入回归 |
| 长纵深场景在单一镜头下失去可读性 | high/high | 房间缩成远景、墙体遮挡交互 | 白天分房间预设镜头，夜间跟随镜头；用真实截图逐房间校位 |
| 夜间移动与覆盖层／拖拽争夺输入 | high/medium | 操作卡片时灵体误走、点击柜位时移动 | 统一输入门禁；覆盖层、对话、检视打开时暂停世界移动 |
| 房间管理员喧宾夺主 | medium/medium | 玩家误认管理员为主角 | 原型只承担视角锚点与空间引导，正式人格另行定案 |
