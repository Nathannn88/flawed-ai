# 传播对照表（propagation matrix）

> **这是"提示"，不是"保证"。** 它告诉你某类输入**该特别看哪、建什么关联、动不动术语表**，帮你更快更准。
> 但它**再不全也不影响漏不漏**——漏不漏由 SKILL.md 的机制（根递归扫 + 依赖图 + 语义通读 + 独立审计 + 循环验证）兜底。
> 遇到这里没列的新类型：照核心原则把它归到最接近的板块，正常走流程；事后若高频，补一行进本表。

板块路径与依赖图见 [`../config.json`](../config.json)。

## 按操作类型

- **新增**：定板块 → 放对文件 → **双向建关联**（新实体 ↔ 既有相关实体互链）→ 加进该板块 MAP → 新名词登记术语表 → 若有 Obsidian 源，更新源文件索引。
- **更新**：grep 别名集找全每一处 → 逐处改 → 一致性复核 → 循环验证。
- **替换淘汰**：新内容就位 → 旧引用**全部重指** → 旧内容归档/留痕 → 回扫确认零残留（do_not_touch 历史除外）。

## 特别说明的几类（高频或高风险）

### 名字 / 命名（最经典的漏网）
- 先从主旨 §11 取该实体**全部别名/称谓/本名**，grep **整个别名集**，不只主名。
- 当心**子串误匹配**（旧名是别的词的一部分）和**全角/半角、中英标点变体**导致 grep 漏匹配——用变体都扫一遍。
- 改完务必登记/更新术语表里的名字与状态。

### 剧情关系（必双端）
- 列出关系**所有端点**，每个端点当独立实体各扫一遍。
- 关系本身可能被第三方文档描述（如"萨满五子继承诗人五智慧"写在世界观里）——语义通读要覆盖这种"描述关系的旁观文档"。

### 设定背景 / 世界观（上游，牵一发动全身）
- story 是基础层：改它**必查 character + system + style 三个下游**是否仍自洽。
- 下游若因此过时 → 一并更新或标记为新的开放问题。

### 主旨变更（最高爆炸半径）
- 新内容**成为新权威**，没有"与主旨冲突"闸门。
- 触发：全部下游板块 re-sync + **所有设计文稿对新主旨逐节一致性复核**（旧文稿现在可能违背新权威）。
- 改了 §11 术语表的词 = 全仓重命名级传播，别名集要含新旧两版。

### 开放问题定案（高频）
- 从 `进度.md` 开放问题**删除**该条 → `决策与活动日志.md` 记 `[决策]`（谁定、为什么、否决了什么）。
- 把"现在定下来的设定"当一次**新增/更新**正常传播进所有相关文稿（定案前可能多处写着"待定"，要找出来落实）。
