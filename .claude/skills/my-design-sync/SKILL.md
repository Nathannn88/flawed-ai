# my-design-sync — 设计变更全量传播引擎

> **唯一目标：让"漏改某处"在结构上几乎不可能发生。**
> 一个疏漏要存活，必须同时骗过九层防线（见末尾）。完整性**不靠记忆、不靠一张位置清单**，靠机制。

读取项目结构：[`config.json`](config.json)（板块/依赖图/特殊文件/记录/红线/验证参数）。
分类提示：[`references/propagation-matrix.md`](references/propagation-matrix.md)（按输入类型给"特别看哪、建什么关联"的提示——**它再不全也不影响漏不漏**，漏不漏由本流程兜底）。
教训库：[`gotchas.md`](gotchas.md)——**每次运行开头必读**。

---

## 核心原则（先内化，再执行）

1. **与类型无关**：无论用户丢的是哪类设计（甚至是 matrix 没列过的新类型），都走同一套引擎。枚举类型本身就是遗漏源——完整性由"根递归扫描 + 依赖图 + 语义通读 + 独立审计 + 循环到干净"保证，不依赖类型被预先列过。
2. **主旨是权威，但也可能是输入**：别的改动与主旨冲突 → 停下报告，不擅改主旨。但当**输入就是改主旨**时，逻辑反转：新内容成为新权威，触发全板块下游 re-sync（见 Phase B 分支）。
3. **不静默跳过**：任何"我觉得这处不相关"都必须在覆盖报告里留痕（状态 + 原因），交用户审。静默 = 用户最怕的那种漏。
4. **不删历史**：回扫旧概念时，`config.do_not_touch`（v1-archive、决策日志历史条目）里的旧词是史实，只读不改。
5. **push 须用户确认**；commit 可做。

## 流程：六阶段 A–F

> 按改动大小伸缩——改错字走轻量，动设定背景/主旨这种结构性改动全套机器都上。但**Phase D 的循环验证和独立审计每次都跑**（用户明确要求）。

### Phase A — 摄入与拆解

1. **读 gotchas.md**，把历史教训加载进来再动手。
2. **定位输入**：Obsidian 笔记 / 用户粘贴 / repo 内文件？若源在 Obsidian——它是 source of truth，**不把内容复制进 repo**，事后只在 `源文件索引.md` 更新链接（见 config.obsidian）。
3. **拆成离散改动单元**：一份文档常混多个改动（既改名又加角色又调剧情）。逐个单元处理，不当一坨。
4. 每单元**定性**：
   - **操作**：`新增` / `更新` / `替换淘汰`
   - **主板块**：story / character / system / style / 主旨本身（用 matrix 辅助判断；判不准就归最接近的上位板块，宁宽勿漏）
5. **抽实体集**：列出本单元涉及的所有专有名词、角色/岛屿/任务名、概念；**关系类改动列出所有端点**（A 继承 B → A 和 B 都是实体）。

### Phase B — 影响测绘（防漏核心）

1. **读权威**：`项目主旨.md` 相关章节 + §11 术语表。**为每个实体建别名集**（如"诗人"=诗人/诗人之像/神像/化身/本名）——后续 grep 整个别名集，不只主名。
2. **判断是否『主旨变更』分支**：
   - 否（常规）：继续；与主旨冲突 → **一致性闸门**：停下报告，不擅改主旨、不埋矛盾。
   - 是（输入在改主旨）：新内容成为新权威 → 影响范围 = **全部下游板块 + 所有设计文稿对新主旨做一致性复核**（旧文稿可能反而违背新权威，挑出对账）。术语表里的词变了 = 全仓重命名级传播。
3. **词法扫（覆盖每个文件）**：用 Grep **从仓库根递归**搜整个别名集 + 旧概念名 → 记下每个 `文件:行` 命中。从根扫而非按板块逐个找，是"由构造覆盖每个文件"的根基（CLAUDE.md / MAP / PLAN 等元文件天然包含在内）。
4. **语义通读（抓隐式暗指）**：按 `config.dependency_graph`，把受影响板块的**下游 + 同级**文稿**整篇读一遍**，找 grep 抓不到的不点名引用（"庙里被供奉的那位"）。务必覆盖：主旨、四板块正文 + 各 MAP、记录三件套、PLAN、根 also_scan_root。
5. **汇成「影响清单」**：实体集 + 别名集 + 每个受影响 `文件:位置` + 该处拟动作（改/替换/新增关联/不动+原因）。
6. **★ Checkpoint**：把影响清单**摆给用户过目**（含任何与主旨的冲突）。用户确认范围对、无误伤后再动手。大改动尤其要停；小改动可一句话带过但仍要展示清单。

### Phase C — 全量应用

按影响清单逐条改：

- **更新**：原地编辑每一处。
- **替换淘汰**：替换旧内容 → 旧引用全部重指到新概念 → 决定旧内容去向（归档说明 / 决策日志留痕），不留悬空引用。
- **新增**：放到正确板块（用 matrix 的 placement 提示）→ **双向建立关联**（新实体 ↔ 相关既有实体互相链接）→ 加进对应 MAP / 必要时 源文件索引。
- **术语登记**：任何新增/改动的专有名词或术语 → 登记进**主旨 §11 术语表**（这是未来一致性检查的基准，漏了等于拆了防线）。
- 主旨只在"术语登记"或"用户确认的主旨变更"时编辑，**绝不静默改主旨**。

### Phase D — 循环验证（防漏第二层，每次必跑）

> 第一遍的**修改本身会引入新问题**（改名手滑、补内容带出新悬空引用、修 X 牵出 Y）。所以不是"查一遍"，是**循环到一整轮零发现**。

```
round = 1
do {
  a. 全仓回扫所有旧/新概念别名（残留 + 正确性）——确认旧概念零残留(do_not_touch 的历史/归档除外)
  b. 对主旨做一致性复核（术语统一？设定不冲突？）
  c. 独立审计（见下）：
       round 1 → 全量独立重发现 + 对账
       round 2+ → 审计本轮新改动的 delta + 抽查重发现
  d. 收集本轮新发现 → 若有则修复，round++
} while (本轮有新发现 且 round ≤ config.verification.max_rounds)

若超 max_rounds 仍不干净 → 停手，把未收敛的问题报告给用户（结构性问题，需人介入）。
必须以"一整轮零发现"收尾。
```

**独立审计**（每次都跑，对抗式）：spawn 一个子 agent（Explore 或 general-purpose），**只给它实体集 + 别名集 + "独立找出所有受影响位置"，不给它看我的影响清单**。它从零 grep + 通读，再和我的清单对账：
- 它找到而我没有的 → **抓到的漏网**，立即补改，并按 gotchas 规则记一条教训。
- 独立重发现 + 对账，才是对抗价值；否则只是复读结论。

### Phase E — 记录与提交

1. **进度.md**：更新现状；开放问题增删（定案的删、新冒出的加）。
2. **决策与活动日志.md**（append-only，最新在上）：
   - `[决策]`——若本次含**人拍板的设计决策**：谁定的 + 为什么 + 否决了什么。
   - `[活动]`——本次改了/产出了哪些文件（Obsidian 笔记只链接不复制 + 守 project 属性规则）。
3. **源文件索引.md**：若涉及 Obsidian 源，更新链接。
4. **commit**（不 push，见 config.commit）：`design: <一句话变更摘要>`。

### Phase F — 覆盖报告（交用户核验无遗漏）

固定模板输出：

```markdown
## 设计同步覆盖报告

**变更摘要**：<一句话>
**分类**：<操作> × <主板块>（混合则逐单元列）
**实体集 / 别名集**：<列出>

### 逐位置状态（不许静默跳过）
| 文件:位置 | 状态 | 说明 |
|-----------|------|------|
| ... | 已改 / 查过未改 / 归档保留 / 不适用 | <原因> |

**与主旨一致性**：<一致 / 已登记术语 / ⚠️冲突已报未改>
**旧概念残留扫描**：<零残留 / 仅 do_not_touch 历史引用>
**独立审计结论**：<对账无差异 / 审计补抓 N 处(已补)>
**验证轮数**：<N 轮收敛 / ⚠️未收敛已停手>
**开放问题变动**：<关闭 #x / 新增>
**commit**：<hash>（未 push）

> 请核验"逐位置状态"是否有该改未改。发现漏的告诉我，我补改并记入 gotchas。
```

## 学习闭环（越用越好用）

- **读在前**：Phase A 第 1 步必读 gotchas.md。
- **写在后**：用户在覆盖报告里指出漏改，或独立审计抓到漏网 → 按 gotchas.md 头部规则**追加一条教训**（先查重，近似则强化既有条目）。
- **会毕业**：一条教训若"硬到该成机制" → 升级进本 SKILL.md / config.json，并从 gotchas 删除（标记已毕业）。结构性升级走 `official-skill-creator`，不让本 skill 危险地自改主体。
- 诚实地讲：没有绝对零疏漏，但能做到**自我纠正**——漏一次，下次结构上就堵上。

---

## 九层防线（一个疏漏要活下来，得全过）

1. 根递归词法扫（覆盖每个文件）
2. 别名集（破解称谓/化身/本名）
3. 依赖图语义通读（抓隐式暗指）
4. 关系端点全展开
5. 影响清单交用户过目（人审 checkpoint）
6. 独立子 agent 重发现 + 对账（每次跑）
7. 循环验证到一整轮零发现
8. 覆盖报告逐位置状态、不许静默
9. gotchas 读在前·写在后（越用越严）
