# gotchas — my-design-sync 的教训库

> **每次运行开头必读**（SKILL.md Phase A 第 1 步）。这里是"用起来才发现的盲区"，越积越值钱。

## 怎么往这里写（约束我自己）

- **一条 = 一个可泛化的教训，不是事故流水账**。事故压成一个括号触发词，规则才是主体。
  - ❌ `2026-06-16 改诗人名时漏了 character/上贡者设定.md 第 12 行`
  - ✅ `【别名】改/查角色 → 先取全部别名再 grep（曾只 grep 主名漏掉"神像"）`
- **格式**：`- 【类别】什么时候会咬你 → 怎么做`（1 行为主，最多 3 行）。带"什么时候"才能在对的时刻被想起来。
- **先查重再写**：有近似条目就**强化那条**，别堆重复（重复会膨胀、污染上下文）。
- **会毕业**：一条硬到该成机制的教训 → 升级进 SKILL.md / config.json，**从这里删除**（结构性升级走 official-skill-creator）。这里只留还没硬化成流程的软教训。
- **控量**：臃肿了就合并，保持一眼扫完。

## 教训

- 【别名】改/查任何实体 → 先从主旨 §11 取它**全部别名/称谓/本名**，grep 整个别名集，不只主名。
- 【标点变体】grep 旧概念 → 同时试**全角/半角、中英标点、空格**变体；只搜一种写法会漏匹配。
- 【子串误匹配】旧名是别的词的一部分时 → 别盲改，逐处确认语境，避免误伤无关词。
- 【历史引用】回扫旧概念 → `决策与活动日志.md` 历史条目、`v1-archive/` 里的旧词是**史实，只读不改**（见 config.do_not_touch）。
- 【旁观文档】关系/设定常被第三方文档"不点名"描述（如世界观里写"萨满五子继承诗人五智慧"）→ 语义通读要覆盖这种描述关系的旁观文档，光 grep 端点名抓不到。
