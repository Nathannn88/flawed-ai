# /startup — Session 启动检查

> 每次新对话开始时快速扫描项目状态，给用户一份简洁的状态报告。
> **当前项目处于 v3 设计定稿阶段（无代码）**——本检查面向设计协作，不跑测试、不碰编码流程。

---

## 触发

- 每次新开对话时自动执行
- 用户说"项目状态"、"现在什么情况"、"近况"

---

## 流程

### 一、并行读取

同时执行：

- **Read** `记录/进度.md` — 当前版本、阶段、待办、开放问题
- **Read** `记录/决策与活动日志.md`（顶部最新 2–3 条）— 近期决策与活动
- **Read** `design/项目主旨.md`（头部 v3 更新说明）— 仅当进度板提示设计有大变动时

> ❄️ 代码阶段才需要的检查（`npm test`、设计→代码应用、`design/*/output/` 扫描）**当前不执行**——v3 一行代码还没写。相应编码 skill 已删，待编码阶段按 v3 重建。

### 二、检查未提交改动

`git status` → 关注未提交改动、未跟踪文件、当前分支。

> ⚠️ 本项目设计稿常出现"改了一大批却没提交"的情况（音频整理、Obsidian 同步后）。**未提交改动是首要汇报项**——提醒用户是否要 commit 存档（push 须用户确认）。

### 三、输出状态报告

> 不超过 20 行。一切正常的项不用列出 — 只报告异常、未提交改动和待办。

输出格式：

```
## 项目状态

**版本**：v3 · **阶段**：设计定稿中（无代码）
**分支**：[branch] · **未提交改动**：有（N 个文件）/ 无

### 近期（决策与活动日志最新几条）
- ...

### 待办 / 开放问题（前 3 项）
- ...（从 记录/进度.md 提取，优先列"最优先"的开放问题）

### 注意
- [未提交改动 → 是否 commit 存档 / 其他异常]

下一步做什么？
```

---

## 记得

- 报告完顺手判断：有**未提交的设计改动**就提醒存档；长对话里出现**重要原始需求**时提醒用户 `/my-snapshot`（手动）。
- 不擅自 push、不擅自 commit（除非用户已授权）。
