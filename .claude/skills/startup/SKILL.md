# /startup — Session 启动检查

> 每次新对话开始时快速扫描项目状态，给用户一份简洁的状态报告。
> **当前项目处于 v3.1 持续可玩原型开发与最小纵向切片验证阶段**——`prototype/temple-mvp/` 是当前活动实现，`project/` 仍是待裁定的旧骨架。

---

## 触发

- 每次新开对话时自动执行
- 用户说"项目状态"、"现在什么情况"、"近况"

---

## 流程

### 一、并行读取

同时执行：

- **读取** `记录/进度.md` — 当前版本、阶段、待办、开放问题
- **读取** `记录/决策与活动日志.md`（顶部最新 2–3 条）— 近期决策与活动
- **读取** `design/设计资料索引.md` — 当前有效设计与素材导航
- **读取** `design/00-项目核心/最高设计权威.md`（相关章节）— 仅当进度板提示设计有大变动时
- **读取** `.agent/long-task/STATE.md` — 仅当文件存在；恢复未完成目标、当前里程碑、验证缺口和精确下一步
- **读取** `prototype/temple-mvp/视觉与交互验收规范.md` — 仅当活动任务涉及 UI、3D、模型、材质、构图、动效或交互反馈

若进度板或长任务状态显示活动原型存在未完成实现／验证：

- 运行成本最低且与当前改动相关的自动测试或 smoke，不默认重跑无关检查；
- UI／3D 改动若缺真实视觉证据，优先恢复浏览器验收：主动截图，动态表现按能力录制短屏或连续截图，并亲眼分析画风、构图、遮挡、层级、色彩、可读性和反馈；
- 浏览器／录屏能力不可用时报告 `BLOCKED` 与解除条件，不用静态检查冒充视觉通过。

### 二、检查未提交改动

`git status` → 关注未提交改动、未跟踪文件、当前分支。

> ⚠️ 本项目设计稿常出现"改了一大批却没提交"的情况（音频整理、Obsidian 同步后）。**未提交改动是首要汇报项**——提醒用户是否要 commit 存档（push 须用户确认）。

### 三、输出状态报告

> 不超过 20 行。一切正常的项不用列出 — 只报告异常、未提交改动和待办。

输出格式：

```
## 项目状态

**版本**：v3.1 · **阶段**：持续可玩原型开发与最小纵向切片验证
**分支**：[branch] · **未提交改动**：有（N 个文件）/ 无

### 近期（决策与活动日志最新几条）
- ...

### 待办 / 开放问题（前 3 项）
- ...（从 记录/进度.md 提取，优先列"最优先"的开放问题）

### 注意
- [未提交改动 → 是否 commit 存档 / 未完成视觉验收 / 其他异常]

下一步做什么？
```

---

## 记得

- 报告完顺手判断：有**未提交的设计改动**就提醒存档；长对话里出现**重要原始需求**时提醒用户 `/my-snapshot`（手动）。
- 活动任务有清晰安全下一步时直接恢复推进，不在每次新会话重新讨论已经确认的契约。
- UI／3D 的截图／录屏和画风分析属于完成条件，不是可选美化步骤。
- 不擅自 push、不擅自 commit（除非用户已授权）。
