# 会议录音 → 高可读纪要

> 目标不是把转写缩短，而是把会议整理成一条可信、可扫描、能推动项目继续前进的证据链。

先读：

1. `config.json`：路径、Whisper 参数、frontmatter。
2. `gotchas.md`：真实失败模式。
3. 项目最高权威、进度和记录规则。
4. 项目记忆 `team-structure.md`：人名与代号映射。本 Skill 不保存真名。

---

## Quick Reference

```text
录音/转写
  → ① GPU 转写（已有完整转写则复用）
  → ② 清理噪音并建立事实表
  → ③ 判断会议类型
  → ④ 重建讨论主线
  → ⑤ 分开会议事实、会后确认、AI 分析
  → ⑥ 本地 + Obsidian 双落地
  → ⑦ 自动同步项目记录
  → ⑧ 一致性自检
```

只有两种情况需要暂停询问：

- 出现项目花名册没有的新成员，必须询问代号。
- 用户要求修改既有 Atlas 笔记但没有明确授权覆盖；遵守 Obsidian 权限规则。

项目记录默认自动同步，不再询问“要不要落记录”。

## ① 转写：必须 GPU

本机有 RTX 5090，任何新转写必须走 GPU：

```bash
bash ".claude/skills/my-meeting-notes/scripts/transcribe.sh" "<录音绝对路径>"
```

脚本执行 GPU 自检、抽取 16k mono 音频，并用 `whisper --device cuda` 生成 `<原名>_audio.txt`。

若脚本报告 GPU 不可用，先修复 CUDA 版 Torch：

```bash
python -m pip install --upgrade torch --index-url https://download.pytorch.org/whl/cu128
```

不要退回 CPU。已有完整转写时直接复用，不为“重新整理”重复推理。

## ② 先建事实表，再开始写

通读完整转写，先在内部把内容分为：

| 类型 | 判定标准 |
|------|----------|
| **已确认决策** | 有清楚的拍板、同意、执行口径或明确排除项 |
| **方向性共识** | 多方认可方向，但具体规格仍未完成 |
| **会议提案** | “可以、可能、我觉得、要不要、先试试”等讨论性方案 |
| **开放问题** | 明确未解、存在分歧、依赖后续调查或选择 |
| **明确任务** | 有负责人或明确承接主体；没有负责人时只能写“待分配” |
| **噪音** | 寒暄、设备调试、跑题、门铃中断、口水重复、静音幻觉 |

判断规则：

- 语气强烈不等于已经拍板。
- 被反复讨论不等于形成共识。
- AI 不得替会议创建负责人、deadline 或否决项。
- 转写含混时保留不确定性，不补猜人名和结论。

## ③ 判断会议类型，决定分析深度

### A. 设计 / 战略 / 产品决策会

使用完整分析：

1. 会议试图解决的底层问题是什么；
2. 玩家/用户价值链是否连续；
3. 是否同时叠加多个各有冷启动的产品；
4. 新方向是否与项目最高权威冲突；
5. 是否涉及隐私、控制权或退出机制；
6. 能否缩成一个可观察、可证伪的最小纵向切片。

### B. 例行同步 / 工作交接会

分析限制为 1–3 条高信号内容：

- 依赖与阻塞；
- 优先级冲突；
- 缺失责任人或 deadline；
- 最短下一步。

任务与状态必须是主体，AI 分析不能喧宾夺主。

### C. 信息播报 / 行政会

没有实质判断价值时省略 AI 分析。不要为了格式生成泛泛建议。

---

## ④ 重建讨论主线

不要机械照时间线复述，也不要把同一观点分散到多个章节。

优先结构：

```text
问题是什么
  → 为什么重要
  → 会中提出了哪些方案
  → 哪些已经确认
  → 哪些仍未解决
```

推荐的纪要顺序：

1. **30 秒读完**：会议目标、最重要结论、最大未决冲突、下一步。
2. **会议结果地图**：只用一张表集中呈现状态。
3. **讨论主线**：按问题链组织，不按说话人堆砌。
4. **决策、任务与开放问题**。
5. **会后确认**：仅记录会议之后由人类明确拍板的内容，并标日期。
6. **AI 分析与建议（非会议结论）**：按会议类型控制深度。
7. **与项目权威的一致性检查**。
8. **来源与保真说明**。

### 可读性目标

- 队友 30 秒内能回答“这场会定了什么、没定什么、我需要做什么”。
- 一段只表达一个判断；超过 3 行的密集段落拆开。
- 表格只用于真正并列的信息，避免用组件数量冒充结构。
- 细节可放折叠 callout，正文保留主线。
- 同一观点只在一个主要位置完整解释，其他位置用链接或短句指回。

---

## ⑤ 权威分层：事实与观点不能混写

纪要中固定使用以下标签：

- `已确认决策`
- `方向性共识`
- `会议提案`
- `开放问题`
- `会后由用户/团队确认`
- `AI 分析与建议（非会议结论）`

AI 分析区必须声明：

> 本节是会后分析，不代表会议结论。只有经用户或团队明确确认后，才可转入项目决策或权威设计文稿。

AI 建议应包含推导依据，而不是只有结论。优先使用：

```text
观察到的会议事实
  → 暴露的矛盾/风险
  → 为什么影响目标
  → 建议的最小验证
  → 用什么结果判断继续或停止
```

若用户之后认可某条建议：

- 在纪要中放入“会后确认”，标明日期和确认主体；
- 按项目规则同步主旨、进度或决策日志；
- 不回写成“会议当天已经决定”。

---

## ⑥ 人名规则

- 所有人名一律使用字母代号，不写中文全名。
- 成员平等呈现，不写老板、创始人、次级合伙人或谁带谁。
- 任务格式统一为 `代号 — 板块/任务`。
- 新面孔不自行编代号，暂停询问用户。
- 无法可靠区分说话者时，不把观点强行归给个人。

## ⑦ 双落地

| 位置 | 文件 |
|------|------|
| 本地 `source_dir` | `<原名>_audio.txt`、`<原名>_会议总结.md`（无 frontmatter） |
| Obsidian `obsidian_dir` | `神像供奉游戏 · 会议纪要 <日期>.md`（带项目 frontmatter） |

两份正文语义一致，Obsidian 版只额外包含 frontmatter 和必要 wikilink。

修改任一版本后同步另一份，并复核：

- 无真名或旧代号残留；
- 决策状态一致；
- AI 分析标签一致；
- 来源路径一致。

---

## ⑧ 自动同步项目记录

每次会议整理完成后自动执行：

- `记录/决策与活动日志.md`
  - 加 `[活动]`：会议、产物与 Obsidian 链接；
  - 只有人类真实拍板的重大事项才写 `[决策]`；
  - AI 建议不得写成项目决策。

- `记录/进度.md`
  - 更新开放问题、分工、状态和日期；
  - 高价值但未确认的 AI 判断可进入“待验证工作假设”，必须标非决策。

- `记录/源文件索引.md`
  - 新会议文件需要索引时更新；
  - 只链接，不复制 Obsidian 正文。

若会议方向与最高权威冲突：

- 列出冲突；
- 保持开放问题；
- 等人类裁定；
- 不擅自修改核心机制。

## Anti-Patterns

| 反模式 | 为什么错 | 改成 |
|--------|---------|------|
| 用很多表格/callout，但读完仍不知道会议主线 | 格式替代了逻辑 | 先重建“问题 → 方案 → 状态”再排版 |
| 把 AI 建议写进“会议决定” | 伪造权威与历史 | 单列“AI 分析与建议（非会议结论）” |
| 把“我觉得/可以试试”写成拍板 | 口语强度不等于共识 | 标为会议提案或开放问题 |
| 所有会议都套完整第一性原理分析 | 例行会被分析淹没 | 按会议类型自适应 |
| AI 为未分配事项补负责人或 deadline | 制造虚假承诺 | 明写“待分配/未明确” |
| 发现主旨冲突后直接改权威文件 | 跳过人类裁定 | 记录冲突并等待拍板 |
| 只改 Obsidian 或只改本地版 | 两份事实漂移 | 双落地同步复核 |

## Quality Gate

- [ ] 已读完整转写，而非只读旧总结。
- [ ] 30 秒摘要包含目标、结论、冲突和下一步。
- [ ] 决策、共识、提案、开放问题彼此分开。
- [ ] AI 观点全部位于明确标注的非会议结论区域。
- [ ] 会后确认带日期，没有伪装成会议原话。
- [ ] 没有虚构负责人、deadline、人名或否决项。
- [ ] 与最高权威的冲突已显式列出。
- [ ] 本地版与 Obsidian 版正文一致。
- [ ] 项目记录已自动同步。
- [ ] 新转写使用 GPU；已有完整转写未重复运行。

## Related / Out of Scope

- 普通知识、文章或资料整理 → 使用 `my-obsidian-note-organizer`，不默认加入会议式深度分析。
- 具体系统机制的正式改写 → 走项目设计同步规则；会议提案本身不等于授权。
- 人员代号映射 → 项目记忆 `team-structure.md`。
