# 会议录音 → 会议纪要

把一段会议录音转写并整理成**给人读着舒服**的会议纪要。这是 flawed-ai 团队的固定工作流：每隔一阵就有一段新的 meeting 录音要整理。

> **先读 `config.json`**（路径、whisper 参数、frontmatter）和 **`gotchas.md`**（踩过的坑，信号最强）。人名映射读**项目记忆 `team-structure.md`**，本 skill 不存真名。

---

## 流程总览

```
录音文件 → ① GPU 转写 → ② 通读剔闲聊 → ③ 套模板写纪要 → ④ 双落地 → ⑤ 问是否进项目记录
```

整个过程只跟用户确认两件事：**人名代号有没有新面孔**、**要不要落进 `记录/`**。其余直接做。

---

## ① 转写（必须 GPU，禁止 CPU）

本机有 RTX 5090——**任何转写走 GPU**。直接调用打包脚本（用 Bash 工具跑，git bash 里 `whisper`/`ffmpeg` 都在 PATH）：

```bash
bash ".claude/skills/my-meeting-notes/scripts/transcribe.sh" "<录音绝对路径>"
```

脚本做三件事：GPU 自检 → `ffmpeg` 抽音频（16k mono mp3）→ `whisper --device cuda` 转写出 `<原名>_audio.txt`。

**若脚本报 GPU 不可用**：说明装的是纯 CPU 版 torch，先 `python -m pip install --upgrade torch --index-url https://download.pytorch.org/whl/cu128` 再重跑。**绝不退回 CPU**（见 [gotchas](gotchas.md)）。

> 35 分钟录音在 5090 上 medium 模型约 6 分钟。更长的录音可后台跑（`run_in_background`），跑完再继续。

---

## ② 通读、剔闲聊

`Read` 转写稿全文，凭语义理解谁说了什么、要做什么。**剔除**：寒暄、设备/网络调试、口水话、跑题八卦、whisper 对静音的幻觉重复。**保留**：设计/机制、分工任务、决策、deadline、开放问题。

口语转写**不可靠**，尤其人名（见 [gotchas](gotchas.md)）。按**角色 + 上下文**判断归属，拿不准就标注"按角色对应，若有出入以实际为准"。

---

## ③ 写纪要（高可读性是唯一硬目标）

**没有固定模板。** 每场会议差别很大——可能是工作衔接（按人分任务最清楚）、可能是剧情/世界观讨论（按议题或时间线组织更顺）、可能是纯决策拍板。**先判断这场会议是什么类型，再决定用什么结构**。结构服务内容，不是反过来。

唯一不变的两条：

- **frontmatter**（仅 Obsidian 版）——`config.json` 里的 `project` 双链 + 精简 tag。这是项目硬规范。
- **人名规则**（见下）。

其余全凭判断。下面是一套**可选积木**，按需取用、自由增删排序，不要为凑齐而硬塞：

| 积木 | 什么时候用 |
|------|-----------|
| `> [!abstract]` 一句话 TL;DR | 几乎总有用——开篇点明这场会要解决什么 |
| `> [!note]` 人员代号图例 | 有多人出场、需要对照代号时 |
| 速查表（谁/做什么/期限/优先级） | **工作衔接型**会议，分工明确时最有用 |
| 各人任务 checklist（`- [ ]`） | 有明确待办、要追踪进度时 |
| 按议题/章节分小节 | **设计/剧情讨论型**会议，内容围绕主题而非人 |
| `> [!success]` 决策 / `> [!question]` 开放问题 | 有拍板或有悬而未决的事时 |
| 时间线 / 流程图 | 讨论顺序或机制流程时 |
| `> [!info]` 来源 | 结尾标录音日期/时长/转写方式 + 本地路径 |

> **可读性铁律**：能扫一眼看懂就别写成大段话。优先表格、callout、加粗关键词、checklist。长段落（>3 行）拆开。目标是队友 30 秒能抓住"这场会定了什么、我要干什么"。

### 人名规则（硬性）

- **所有人名一律用字母代号**（如 wxn / wxr / LYZ / GYY / ZF），不写中文全名。映射查**项目记忆 `team-structure.md`**。
- **成员平等呈现**——纪要里**绝不**写"创始人 / 老板 / 次级合伙人 / 谁带谁"等身份层级。层级仅供你内部理解，不落到文件。
- **每人格式统一**：`代号 — 板块`（如 `LYZ — 美术·场景`），不给某个人加额外头衔/旁白。
- **遇到新面孔**：转写里出现 roster 没有的人 → 停下来问用户该用什么代号，别自己编。

## ④ 双落地

| 落到哪 | 文件 |
|--------|------|
| 本地（`config.json` 的 `source_dir`） | `<原名>_audio.txt`（转写）、`<原名>_会议总结.md`（纯净版总结，无 frontmatter） |
| Obsidian（`obsidian_dir`） | `神像供奉游戏 · 会议纪要 <日期>.md`（带 frontmatter，链回上一篇纪要） |

两份信息一致，只是 Obsidian 版多 frontmatter。改名/改代号时**两份同步改**（用 `replace_all`，并 `Grep` 复核无真名残留）。

---

## ⑤ 收尾

按项目记录铁律，问用户要不要：
- `记录/决策与活动日志.md` 加一条 `[活动]`（链接这篇纪要）+ 重大决策标 `[决策]`；
- `记录/进度.md` 同步开放问题。

不自己擅自写 `记录/`，等用户点头。
