# Gotchas — 踩过的坑

> 这里记录用本 skill 时反复犯的错。比正文指令更值钱，因为针对真实失败点。新坑随手补。

## 1. 默认用了 CPU 转写（最高频）

- **现象**：whisper 跑得极慢（35 分钟录音要一两小时）。
- **原因**：系统全局 Windows Store Python 装的是 `torch x.x+cpu` 纯 CPU 版，`torch.cuda.is_available()` 为 False，whisper 默默退回 CPU。
- **正确做法**：本机有 RTX 5090，**任何转写必须 GPU**。`transcribe.sh` 已带自检——若报 GPU 不可用，先
  `python -m pip install --upgrade torch --index-url https://download.pytorch.org/whl/cu128`
  （5090 是 Blackwell，必须 cu128 构建）再重跑。**绝不退回 CPU。**

## 2. 人名被转写得乱七八糟

- **现象**：同一个人在转写稿里出现好几个名字（如"王鑫然/王新来/王鑫来/王先生"）。
- **原因**：whisper 对中文人名基本靠猜，没有声纹分离。
- **正确做法**：按**角色 + 上下文**判断归属，对照项目记忆 `team-structure.md` 的花名册映射到字母代号。拿不准就在来源说明里标"按角色对应，若有出入以实际为准"。出现 roster 里没有的新人 → 停下来问用户用什么代号，别自己编。

## 3. 写了身份层级 / 给某人加头衔

- **现象**：纪要里冒出"老板""创始人""会议主导者"之类。
- **原因**：从录音里能听出谁主导、团队记忆里也有创始人/合伙人层级。
- **正确做法**：**文件里成员一律平等**，统一为「代号 — 板块」。层级只供内部理解，绝不落到文件。

## 4. 硬套模板

- **现象**：不管什么会都套"速查表 + 各人 checklist"。
- **原因**：图省事照搬上一篇。
- **正确做法**：先判断会议类型（工作衔接 / 剧情讨论 / 决策）再定结构。剧情讨论按议题组织比按人分任务更可读。结构服务内容。

## 5. 两份文件改名不同步

- **现象**：改了代号或措辞，只改了 Obsidian 版，本地 `_会议总结.md` 还是旧的（反之亦然）。
- **正确做法**：任何改名/改代号用 `replace_all` 两份一起改，最后 `Grep` 复核两份都无真名/旧称残留。

## 6. whisper 对静音段产生幻觉重复

- **现象**：转写里某句话莫名重复几十遍。
- **原因**：whisper 对长静音/噪音会"复读"。
- **正确做法**：通读时直接当闲聊剔掉，别当成真实内容。
