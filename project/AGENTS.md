# 代码层（待裁定的旧验证骨架）

> `project/` 是较早设计阶段留下的 Vite + React + TypeScript 验证骨架，目前冻结。
> v3.1 的设计权威是 `../design/00-项目核心/最高设计权威.md`，完整导航见 `../design/设计资料索引.md`。
> 当前持续演进的可玩产品原型位于 `../prototype/temple-mvp/`；“继续推进”默认指活动原型，不得误写到本目录。

## 当前裁定

- 此目录不是 v3.1 的实现真相，旧循环、界面与参数不能自动沿用。
- 在最小可玩切片规格定稿、并明确复用边界前，不继续添加正式功能。
- 已淘汰实现不在本目录保留；历史证据不得作为当前模块或设计判断的默认来源。

## 技术现状

- Vite + React + TypeScript，纯客户端。
- 旧结构以 `src/game/` 放纯逻辑、`src/ui/` 放渲染，仍可作为架构候选，不代表已被 v3.1 采纳。
- 本地命令：`npm install`、`npm run dev`、`npm run build`。
- API 密钥只能放 `.env.local`，禁止硬编码或提交。

## 设计与资产边界

1. 任何功能开始前，先读取最高设计权威和对应设计文稿。
2. `design/40-美术素材/` 保存源资产；运行时选用的文件复制或转换到 `project/public/assets/` 或 `project/src/assets/`。
3. 代码、构建配置、CSS 和清单文件不得以相对路径直接读取 `../design/`。
4. 复制时在 `design/40-美术素材/素材索引.md` 登记源文件、运行时副本及用途。
5. 源资产更新后，不静默覆盖代码副本；先确认是否需要重新导出、压缩或兼容性处理。

## 正式重启编码前的门槛

1. 最小切片有清晰的起点、玩家动作、反馈、结束条件和验收标准。
2. 明确此骨架是复用、部分复用还是归档。
3. 按 v3.1 重写模块表、测试策略、部署方式与质量链。
4. 对首批运行时资产完成来源、许可证、格式和性能检查。

## 重启后的协作与验收要求

- 真正决定复用或迁入本目录后，先把根规则、`../写作方式说明.md`、活动原型状态和 `../prototype/temple-mvp/视觉与交互验收规范.md` 转换为本工程的模块表与验收入口，不能只复制旧代码。
- 清晰、已授权的实现任务持续推进到可验证结果；会改变迁移范围、架构方向、永久数据或对外发布的事项才停下确认。
- UI、3D 场景、模型、材质、构图、动效或交互反馈变更必须在真实页面中主动截图，并实际分析画风、遮挡、层级、色彩、可读性和交互暗示；动态表现优先录屏或连续截图。自动测试、DOM 和坐标只提供逻辑证据，浏览器或录屏不可用时必须标记 `BLOCKED`，不得宣布视觉验收通过。
- 长任务记录当前动作、证据、阻塞和恢复入口；最终汇报明确区分 `PASS`、`BLOCKED` 与尚未验证。
